# TAAS Demo Runbook

目標展示日：2026-10-24  
建議展示長度：6–8 分鐘  
主要觀眾：臺北市政府／黑客松評審

## 1. 部署前一次性設定

目前主機的 `/var/run/docker.sock` 是 `nobody:nogroup` 且使用者 `datafox` 無存取權，因此程式已備妥但本帳號無法完成映像建立。請由主機管理員選一種方式處理：

1. 以有 Docker 權限的帳號在本目錄執行部署；或
2. 修正 Docker daemon socket 為標準 `root:docker`，再把 `datafox` 加入 `docker` 群組並重新登入。

Docker 群組等同主機 root 級權限，不應用 `chmod 666 /var/run/docker.sock` 當捷徑。

權限完成後：

```bash
cd /storage/ssd3/datafox/TAAS
docker compose up --build -d
docker compose ps
curl --fail http://127.0.0.1:8000/api/health
```

正式公開需要既有反向代理把 HTTPS 網域轉送至 `127.0.0.1:8000`。Caddy 範例位於 `deploy/Caddyfile.example`；替換網域並讓 DNS 指向主機即可。不要讓 `.env`、TDX token endpoint 或 `data/raw` 對外提供。

## 2. 每次更新資料

原始資料已存在時，重建可提交 demo：

```bash
uv run python scripts/build_demo_data.py
find data/raw data/demo -type f -print0 | sort -z | xargs -0 sha256sum > data/CHECKSUMS.sha256
uv run pytest
```

產物是確定性的：相同原始檔會得到相同 CSV 與 gzip checksum。

## 3. 展示前 30 分鐘

```bash
docker compose ps
curl --fail http://127.0.0.1:8000/api/health
TAAS_BASE_URL=http://127.0.0.1:8000 uv run python scripts/smoke.py
```

人工檢查：

- 首頁顯示代表日 `2026-10-06`。
- 時間軸可從 07:00 移到 09:29。
- 切換堤頂、民權、南京與園區核心後，點位及曲線同步變化。
- 成功轉搭率改成 0% 時，班次與成本必須為 0。
- 切換三種成本分攤，四方金額總和等於每日成本。
- 關閉網路後，除 OSM 底圖外仍可操作；本地 SVG 點位層、模型與圖表不得失效。

## 4. 6–8 分鐘展示腳本

### 0:00–1:00｜問題與資料可信度

「這不是把壅塞畫得更漂亮，而是把政策選項放在同一個可追溯的比較框架。青色是觀測，紫色是衍生，黃色是使用者假設。」

指出代表日、56 個 VD、150 分鐘與資料完整率；主動說明單日不是典型平日。

### 1:00–2:30｜晨峰熱點

拖動時間軸，依序切換堤頂大道、民權走廊與園區核心。指出最高 15 分鐘區間與速度變化。不要說「這就是全部進入內科的車」，應說「選定偵測器的車流通過量」。

### 2:30–4:30｜三類政策不是同一件事

- 分批上班：固定 cohort 前後錯開，降低尖峰但不消滅旅次。
- 彈性工時：把到班時間分散在整個時窗。
- 點對點接駁：改變運具，減少汽機車但新增大型車班次。

展示組合方案，強調系統依序套用，不直接把改善百分比相加。

### 4:30–6:30｜核心決策互動

把成功轉搭率從 5% 拉到 15%／25%，同步讀出：

- 成功轉搭人數。
- 淨減汽機車旅次。
- 單向班次與所需車隊。
- 每位乘客成本。

再切換「企業主導、均衡共擔、政策啟動」三種公私協力分攤。

### 6:30–7:30｜結論與下一步

「市府現在可以決定試辦母體、期望轉搭門檻與補助結構，並立刻看到所需車隊與可能的車流量級。下一步不是相信模型，而是用多日 VD、企業匿名調查與業者報價，逐層替換黃色假設。」

## 5. 現場降級

- **無網路**：繼續使用本地資料與 SVG 點位；不要花時間修 OSM 圖磚。
- **Docker 無法啟動**：`uv run uvicorn taas.main:app --host 0.0.0.0 --port 8000`。
- **公開 URL 失效**：由簡報機直接開 `http://127.0.0.1:8000`。
- **資料問題**：回到預設值，只展示已驗證的 2026-10-06 代表日。
- **評審追問精確預測**：回答這是情境邊界與試辦設計工具；未取得員工偏好前不宣稱已校準。

## 6. Demo 後才做

- 把入口 VD 人工整理為不重複 screenline。
- 補抓 5–10 個正常工作日並建立中位數及四分位範圍。
- 用 2–3 家同規格報價替換每日每車假設。
- 用企業匿名調查校準轉搭率，而不是讓敏感性滑桿永久充當預測模型。
